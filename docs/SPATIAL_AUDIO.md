# IEMクライアント音響

Minecraft 26.3 / IEM_Compatibility。初期状態は有効。サーバープラグイン・Tois Armoryデータパックの変更は不要。

## 動作

- 位置を持ち、距離減衰を使う効果音に `AL_SOFT_source_spatialize` を適用する。ステレオ素材も発生位置で空間化する。
- ステレオはOpenAL内でモノラルに合成される。合成ゲインを0.5倍にして、相関のある左右を加算した際の増幅を防ぐ。聞き手と完全同位置の場合はOpenALがステレオを維持するため0.5倍にせず、その例外にも追従する。元のステレオ幅や逆相成分を保存する処理ではない。
- IEM音響ON時はHRTFを要求する。要求成功と実際の有効化は別なので `/iemaudio status` で状態を確認する。OFF時はMinecraftの指向性オーディオ設定に戻る。OSの設定を書き換えない。
- 相対音、距離減衰なしの音、音楽・レコード・天候・環境・VOICE・UIカテゴリは変更しない。IEMの無線、レイド終了演出、PDA、リザルト、ルート出現音、医療品、バックパック音も除外する。MASTERカテゴリのSCAV音・弾・足音は対象。

## 距離・遮蔽

距離による音量減衰はMinecraftの既存設定を維持する。別の距離減衰を重ねない。距離に応じた穏やかな高域減衰と、実際に壁・床に当たるかによる減衰を追加する。

クライアントの衝突形状で、聞き手のカメラから音源へ中心・左右18cmの3本を調べる。中央値を採用し、窓枠の端を1本だけかすめて急にこもるのを避ける。水は障害物に数えない。葉は弱く、羊毛は強く、その他の衝突形状は通常の遮蔽として扱う。ガラスは衝突するので通常遮蔽になる。材質値はゲーム向けの近似で、実測の透過係数ではない。

通常遮蔽は音量約0.62倍、高域ゲイン約0.47（距離分は別）。EFXの低域通過フィルターで高域を穏やかに減らす。既存SCAVの900/1800Hzローパスのように高域をほぼ消す設定は使わない。高域の残存が上下定位の改善を保証するわけではない。

既に `.muffled` / `.deep` が付いた `iem:scav.voice.*` には追加の距離高域・遮蔽フィルターを掛けない。サーバー側の既存処理を二重に掛けないためであり、その既存音源の高域不足を修復するものではない。

- 追跡は最大96音、レイはクライアントtickの区切り間で最大12本。短い音も、予算が残っていれば再生開始時に計算する。
- 各音の再計算間隔は最低4tick。巡回で処理し、多数同時再生時は更新間隔が延びる。上限超過・初回予算不足では計算を待つため、短い音が遮蔽なしで終わることもある。
- 対象距離は128ブロックまで。未受信チャンクを経由する場合は保守的に遮蔽扱いにし、ロード要求を出さない。角を通る経路もDDAで確認する。
- 音声スレッドからワールドを読まない。目標値を共有し、音声側のtickで音量と高域を補間する。
- レイは各経路の最初の障害物まで。壁厚、複数壁、回折、開口部を通る最短音響経路、反射、残響は未実装。距離を経路長に置き換えるものではない。
- 動く音源はSoundInstanceの更新座標を使う。サーバーが固定位置で送った単発音は、その送信位置のまま。

## 操作

| コマンド | 動作 |
|---|---|
| `/iemconfig` | YACLの設定画面を開く（Mod Menuからも開ける） |
| `/iemaudio` または `status` | 実際のHRTF状態、データ名、拡張対応、処理累計、レイ数 |
| `/iemaudio on` / `off` | IEM音響を切り替える |
| `/iemaudio occlusion on` / `off` | レイによる遮蔽と距離高域処理を切り替える |
| `/iemaudio hrtf` | OpenALが検出したHRTFの一覧 |
| `/iemaudio hrtf <番号>` / `default` | データ選択。番号ではなく名前を保存する |
| `/iemaudio test mono` / `stereo` | 6方向の定位テスト |
| `/iemaudio test stop` | テスト停止 |

切り替えは設定を `config/iem-audio.json` に保存し、サウンドエンジンを再読み込みする。その時点の再生音は止まる。

HRTF追加データは同梱していない。OpenALが検出する `.mhr` を選択できる。追加データの配置・検出にはOpenALのOS別探索先を使い、必要に応じてゲームを再起動する。選択データが見つからなければ既定に戻り、statusで不一致を表示する。

他のMODが同じ音源のEFX直接音フィルターを変更する構成は競合し得る。その場合はIEMのocclusionをOFFにして比較する。Sonar等の外部空間化との併用も比較条件に影響する。

## 検証

1. `./gradlew build`：Minecraft/OpenAL非依存のポリシーテストも実行する。無線等の除外、SCAV二重加工防止、ゲイン、距離減衰の重複防止、負座標・斜め・角での未読込チャンク判定を検証。
2. `python tools/check_audio_native.py /path/to/libopenal.so`：numpyが必要。同梱系列OpenAL Soft 1.25.2のループバックで、ステレオ上下変化、相関ステレオ合成時のゲイン、遮蔽、高域残存、フィルター解放時のエラーなしを検証する。実際の音声デバイスは使わない。
3. `JAVA_HOME=/path/to/jdk25 python tools/check_audio_mixins.py`：FabricのpreLaunchで実際にLibrary/Channel/SoundEngineへMixinを適用する。OpenALのNo OutputバックエンドでHRTFのON/OFF、ステレオ合成ゲイン、EFX、音量更新、補間、解放を検証する。Gradle依存の取得が必要。配布jarにテスト用MODは含めない。
4. 実機：外部空間化を揃え、まず `occlusion off` で同じ場所・向きからON/OFFのmono/stereoテストを比較する。次に遮蔽ONでドアの開閉、同階の壁、上下階、移動中の音源を確認する。

生成用素材は `tools/generate_audio_probe.py` の手続き的ノイズのみ（numpy/soundfile）。Minecraftの音源やコード、外部HRTFデータは同梱しない。

ビルドやループバックで確認できるのは処理の成立まで。上下の正答率、Sonarとの体感差、実ゲームでのCPU負荷は実機検証が必要。
